# Steps 10–13 — Isolation, recovery, comparison, metrics

## Steps 10–11 — Isolation and route recovery

Implemented in `ns3/mbtr-isolation.h`, wired into the simulator. Not compiled.

### Mechanism

A `BlacklistQueueDisc` sits as the root qdisc on every node and discards outgoing
frames whose next-hop MAC is blacklisted. This is the one point in the NS-3 stack
where the next hop is known and the packet can still be stopped, so next-hop
exclusion works without forking AODV.

Three things follow, all of them wanted:

1. Data traffic stops being relayed through the isolated node.
2. Unicast AODV control traffic to it stops, so it can no longer answer into a
   route. Control-plane isolation comes free.
3. The link looks dead to AODV's own failure detection, which raises RERR and
   triggers rediscovery unprompted.

### The claim this supports, and the one it does not

Route recovery here is **AODV's native rediscovery operating under an exclusion
constraint**. It is not a new recovery protocol. Step 11 contributes the exclusion
constraint and the measurement of what it costs — nothing more. Write it that way.
Claiming a novel recovery algorithm would be overreach that a reviewer familiar
with AODV will catch immediately.

### Limitations to state, not hide

- **Ingress is not filtered.** A blacklisted node can still be heard; its
  broadcasts still arrive. Full silencing would need a receive-side hook NS-3
  does not expose cleanly.
- **The qdisc is installed on every run, including clean baselines.** Installing
  it only for isolation arms would confound recovery measurements with a change
  in queue discipline.
- **Isolation is soft state.** A `confirmed` verdict can be revised, so schedules
  carry `release` events and the blacklist expires.

### Verdicts are replayed, not computed in C++

Isolation times come from a CSV generated by the Python pipeline. Two reasons,
both practical: the C++ and Python trust models cannot silently diverge, and
recovery cost becomes measurable independently of detection accuracy. It also makes
the cost of a **false** isolation directly measurable — schedule an honest node and
read the damage off the throughput curve. That experiment should be in the paper.

```
time_s,observer,target,action
60.0,all,2,isolate
```

`observer=all` models fully propagated notification. Per-observer rows model
partial propagation, and the gap between them is the measurable cost of the
notification step.

## Step 12 — The comparison matrix

`scripts/run_comparison.sh`, arms generated by `analysis/make_schedules.py`.

| Arm | Configuration | Purpose |
|---|---|---|
| A | Clean AODV | ceiling |
| B | AODV + malicious beacon, no defence | damage floor |
| C | Detection only, no isolation | shows detection alone is insufficient |
| D | EMBN-style: isolate on first suspicion, never release | closest prior work |
| E | Proposed: confirm, isolate, release if cleared | contribution |

C, D and E consume the **same verdict stream** and differ only in what the network
does with it. Same topology, same mobility, same seeds, one variable.

### Give arm D its real strength

D isolates on first *suspicion*, so it reacts sooner than E, which waits for
confirmation. The expected result is that **D beats E on detection latency and
loses on false-isolation cost**. `tests/test_metrics.py` asserts that D's isolation
time precedes E's, so a strawmanned D fails the test suite rather than reaching a
reviewer.

If E wins on every axis, something is wrong with the comparison, not with the
world. Say what E gives up.

## Step 13 — Metrics

`analysis/metrics.py`, tested in `tests/test_metrics.py` against curves with known
answers.

| Family | Metrics |
|---|---|
| Security | accuracy, precision, recall, F1, FPR, FNR, isolation rate, detection latency |
| Network | PDR, throughput, end-to-end delay, routing overhead, packet loss, energy |
| Recovery | recovery time, recovery ratio, **throughput debt**, degradation ratio |
| Beacon | localization error, RSSI deviation, beacon consistency score |

Three decisions in this module worth defending:

**Classification is scored per node, not per window.** A node confirmed in 40 of 50
windows is one true positive, not forty. Per-window scoring inflates every figure
and is the most common way these tables get overstated.

**Recovery requires sustained throughput.** Return to 90 % of baseline must hold for
five consecutive bins. AODV's post-rediscovery delivery is bursty, and without the
sustain requirement a single lucky bin reads as instant recovery.

**Throughput debt is the discriminating recovery metric.** Two mechanisms that both
eventually recover have identical recovery ratios; the faster one owes less
integrated shortfall. `test_debt_orders_two_mechanisms` asserts exactly this —
recovery ratio fails to separate a 10 s recovery from a 60 s one, and debt does.
Without debt, the central Objective 4 claim about *minimizing impact* has no
supporting number.

**Baseline is measured within-run**, from each run's own pre-attack window, not from
a separate clean run. Cross-run baselines fold in topology and mobility differences.

**Everything is reported as mean ± 95 % CI over at least five seeds.** `aggregate()`
uses the small-sample t critical value; a single run is not a result.
